# Preview canvas backing-store reuse

2026-11-09. Phases4/6/16/25 component evidence only.

## Implementation

The fit and zoom-tile publication branches in App now use the same production
presentPreviewFrame helper. Setting a canvas width/height even to its current value
resets its backing store and context. Matching dimensions now retain both; only
changed axes are resized. Whole-frame drawing uses copy compositing so transparent
pixels replace, rather than blend with, an older edit. The context is restored to
source-over even after a draw error. No processing, resampling, color math or
source image change was introduced. Native parser/decoder and release ownership,
generation checks, histogram payload analysis and actual frame dimensions remain.
No new dependency or third-party code; this integrates the existing browser Canvas
presentation API, not a new image-processing engine.

## Limits and reproduction

This is a modest display optimization, NOT proof that the installed five-second
latency complaint is resolved, not measured GPU time, physical display latency or
Tauri/WebView2 acceptance. It does not avoid the current GPU-to-CPU transport.
It does not improve first full-resolution RAW decode/1:1 latency.

Bundle the fixture module as IIFE StarroomCanvasProbe using existing Rolldown,
inject into isolated Chromium, and call verifyCanvasBackingReuse with an ArrayBuffer
of an actual Native SRP4 RGBA frame generated by preview_transport_probe.
The function requires RGBA, compares all output bytes, closes its ImageBitmap,
and throws on any mismatch. Run with synthetic/public fixture frames only.
Localhost access timed out in this environment; isolated about:blank plus a
Playwright-fulfilled local fixture route avoided a development-server dependency.
