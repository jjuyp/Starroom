## Production changes

- Existing deterministic bilateral NR keeps every spatial/range weight, exponential,
  dy/dx accumulation order, channel arithmetic, strength and edge policy. Column
  clamping/address multiplication is computed once per source column; row addresses
  once per output row. Existing Rayon schedules independent rows instead of pixels.
  Empty shapes remain identity. The extra table is136bytes/source-column plus136bytes
  per active row task, not another full-frame buffer (1024-wide table136KiB).
- Real `PreviewCanvas` no longer requests a forced `willReadFrequently:true` canvas.
  The actual lossless Native RGBA display payload already contains the exact bytes
  needed for the existing RGB histogram; its offset view is borrowed, not copied.
  The existing histogram calculation is unchanged. Interactive RGBA no longer performs
  full `getImageData` solely for histogram analysis. JPEG and read-only demo retain
  explicit decoded-canvas readback; no synthetic histogram or silent fallback.
- Render order, source/prepared/GPU/frame identities, Final JPEG96, full precision
  export, current geometry, Native source image math and existing coefficients stay
  unchanged. No claim that Chromium necessarily selects GPU canvas acceleration.
